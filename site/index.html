Private-network API bridge

Facebook requests.
Cookies stay server-side.

Small, auditable bridge for internal automations. Mount operator-owned Facebook cookies once; call a narrow HTTPS API through curl_cffi browser impersonation.

Get startedOpenAPI 3.1View source

How it works

1 · Export
Export own admin session from J2TEAM Cookies as JSON.
2 · Mount
Read-only cookie file mounted into container.
3 · Integrate
n8n or internal app calls one documented API.
4 · Request
Bridge enforces Facebook HTTPS boundary and returns response.

Built small on purpose

No cookie upload API. No arbitrary web proxy. No hidden browser farm. One transport boundary you can inspect, test, and run privately.

Cookie handling

Mount, never transmit

Cookie JSON remains on host or secret store. Caller cannot pass Cookie headers.

Transport

curl_cffi

Browser-like TLS and HTTP stack. Browser profile configured via environment variable.

Guardrails

Narrow allowlist

HTTPS Facebook hosts only. GET, POST, HEAD only. Structured logs omit bodies and secrets.

API catalog

Swagger-compatible OpenAPI 3.1 contract. Import into Swagger UI, Scalar, Postman, Insomnia, or Redoc.

POST/v1/facebook/request

Send one allowlisted Facebook HTTPS request. Bridge attaches mounted cookie session.

View schema →
curl -X POST http://localhost:8899/v1/facebook/request \
  -H 'content-type: application/json' \
  -d '{
    "method":"GET",
    "url":"https://www.facebook.com/",
    "headers":{"accept":"text/html"}
  }'

Quick start

Use Facebook account and groups you own or administer. A cookie export is a credential. Never commit or share it.

# Export JSON with J2TEAM Cookies, then save it locally
cp ~/Downloads/cookies.json ./cookies_fb.json

# Build and start
docker compose up -d --build

# Verify
curl http://localhost:8899/healthz
J2TEAM setup guiden8n & app integration
